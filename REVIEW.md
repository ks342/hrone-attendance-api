# REVIEW.md

Review of the starter `app/main.py`. Line numbers refer to the starter as shipped in the kit.

| # | Where (function / line) | What is wrong | How you'd notice it (test, input, or symptom) | How you fixed it |
|---|---|---|---|---|
| 1 | `MongoClient(...)`, l.22 | Client is not `tz_aware`, so PyMongo returns **naive** datetimes. Anything read back (punch times, history) loses its time zone and gets interpreted as local time by `.timestamp()`, or can't be compared with aware datetimes at all. | On a server running in IST, a record read back returns `punch_in` shifted by 5h30; comparing a stored punch with `datetime.now(timezone.utc)` raises `TypeError` -> 500. | `MongoClient(..., tz_aware=True, tzinfo=timezone.utc)`; all instants in the code are aware UTC, and `to_ms`/`from_ms` convert at the API boundary. |
| 2 | l.22-23 | Connection details are hard-coded as fallbacks (`localhost`, `attendance_db`). If the grader's variables are missing the app silently talks to a different database. | Start without `MONGO_URI`: app comes up "healthy" against the wrong DB. | Read both from the environment (`.env` only fills gaps, real env wins); fail fast at startup if either is missing. |
| 3 | whole file | **No indexes are created.** Nothing makes `emp_code` or `(emp_code, date)` unique, and every list/analytics query is a collection scan. | `/admin/explain` shows `COLLSCAN`; duplicates appear under concurrency (see 11, 13). | `ensure_indexes()` at startup (idempotent `create_index`), retried from `/health` if MongoDB was not up yet. The index list and the reason for each is in `INDEXES` and DECISIONS.md. |
| 4 | `compute_late_minutes`, l.33-37 | (a) `punch_in.replace(hour=h, ...)` builds the shift start in the punch-in's own time zone (UTC / server-local), not IST. (c) Overnight shifts are ignored: a 00:30 punch for a 22:00 shift is compared with 22:00 of the same day. | Shift 09:30, punch 09:40:01 IST: rule says 10, starter says 0 (and with a UTC timestamp it compares 04:10 UTC with 09:30 and returns 0 for everyone). | Rewrote on top of `shift_bounds(day, emp)`, which builds the shift start in IST on the attendance date (R1). Late iff `seconds > 600`, then `seconds // 60`. Checked: 09:40:00 -> 0, 09:40:01 -> 10, 10:15:59 -> 45, overnight 00:30 -> 150. |
| 5 | `compute_work_hours`, l.40-41 | `round(x, 2)` on a float is not half-up (binary floats + half-even), R4 requires half-up. | 2h 01m 30s = 7290 s = 2.025 h: `round()` gives **2.02**, the rule gives **2.03**. ## Looked at and decided it was fine

* `IST = timezone(timedelta(hours=5, minutes=30))` is correct (India has no DST), kept.
* `load_dotenv()` defaults to `override=False`, so real environment variables already win over `.env`. Kept (made the `override=False` explicit).
* Endpoints are plain `def`, not `async def`. With the synchronous PyMongo driver that is the right choice: FastAPI runs them in its thread pool, so a slow query does not block the event loop. `MongoClient` is thread-safe and shared.
* Storing `date` / `joined_on` / shift times as strings is intended (DATA_MODEL.md), and `"YYYY-MM-DD"` strings sort and range-compare correctly, so the date range filters on strings are fine.
* The helper functions were worth keeping as separate, named functions (the analytics and PATCH reuse them), but not their bodies: all three were rewritten, and they now take the employee and the attendance date so overnight shifts work.
